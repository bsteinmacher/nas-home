# Codebase Structure

**Analysis Date:** 2025-02-13

## Directory Layout

```
[project-root]/
├── lib/               # Flutter source code
│   ├── core/          # Cross-cutting concerns (DI, Theme)
│   ├── data/          # Data layer (Repositories, DataSources)
│   ├── domain/        # Domain layer (Entities, UseCases, Repo Interfaces)
│   └── presentation/  # UI layer (BLoCs, Pages, Widgets)
├── test/              # Tests
├── android/           # Android-specific files
├── ios/               # iOS-specific files
├── linux/             # Linux-specific files
├── web/               # Web-specific files
└── windows/           # Windows-specific files
```

## Directory Purposes

**lib/core:**
- Purpose: Infrastructure and application-wide configurations.
- Contains: Dependency injection setup, theme definitions, constants.
- Key files: `lib/core/di/injection_container.dart`, `lib/core/theme/app_theme.dart`.

**lib/data:**
- Purpose: Implementation details for data fetching and persistence.
- Contains: Repository implementations that coordinate data sources.
- Key files: `lib/data/repositories/nas_repository_impl.dart`, `lib/data/datasources/seerr_datasource.dart`.

**lib/domain:**
- Purpose: The core business logic and definitions of the app.
- Contains: Entities (domain models), Use Cases (actions), and Repository interfaces (contracts).
- Key files: `lib/domain/entities/hardware_info.dart`, `lib/domain/usecases/get_services_status.dart`.

**lib/presentation:**
- Purpose: User interface and its state management.
- Contains: BLoCs (state), Pages (screens), and Widgets (components).
- Key files: `lib/presentation/blocs/nas_status_bloc.dart`, `lib/presentation/pages/home_page.dart`.

## Key File Locations

**Entry Points:**
- `lib/main.dart`: Main entry point for the Flutter application.

**Configuration:**
- `pubspec.yaml`: Project dependencies and metadata.
- `analysis_options.yaml`: Linting and static analysis rules.
- `lib/core/theme/`: UI styling (colors, typography, spacing).

**Core Logic:**
- `lib/domain/usecases/`: Individual business logic operations.

**Testing:**
- `test/widget_test.dart`: Sample widget test.

## Naming Conventions

**Files:**
- snake_case: `home_page.dart`, `nas_status_bloc.dart`.

**Directories:**
- snake_case: `presentation/pages/`.

**Generated Files:**
- `[name].freezed.dart`: Immutable classes generated by Freezed.
- `[name].g.dart`: JSON serialization or other generated code.

## Where to Add New Code

**New Feature (e.g., File Manager):**
1. **Domain:** Create entity in `lib/domain/entities/`, use case in `lib/domain/usecases/`, and repository interface in `lib/domain/repositories/`.
2. **Data:** Create data source in `lib/data/datasources/` and repository implementation in `lib/data/repositories/`.
3. **Presentation:** Create BLoC in `lib/presentation/blocs/`, page in `lib/presentation/pages/`, and widgets in `lib/presentation/widgets/`.
4. **DI:** Register new classes in `lib/core/di/injection_container.dart`.

**New Component/Module:**
- Shared UI components: `lib/presentation/widgets/`.

**Utilities:**
- Shared helpers: `lib/core/utils/` (if it exists) or within specific layer utils.

## Special Directories

**lib/domain/entities:**
- Purpose: Pure models using `freezed` for immutability.
- Generated: Yes (partial via `.freezed.dart`).

**lib/presentation/blocs:**
- Purpose: State management logic.
- Generated: Yes (partial via `.freezed.dart` for events/states).
